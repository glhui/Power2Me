# Skill 学习路线

学习过程优先关注可观察行为，而不是编写很长、看起来完整的指令。

## 阶段一：纯指令 Skill

创建一个目标明确、不带脚本的窄范围 Skill。

学习内容：

- 编写准确的名称和触发描述；
- 定义输入和输出；
- 定义不应触发的请求；
- 定义停止条件；
- 设计少量行为案例。

完成证据：

- Skill 能在目标请求中触发；
- 至少两个相近但无关的请求不会触发；
- 新会话不依赖创建时的聊天记录也能使用它。

## 阶段二：渐进式披露

把大量条件性指导移入 `references/`，并在 `SKILL.md` 中说明何时读取。

完成证据：

- 普通请求不加载无关参考资料；
- Skill 仍能稳定作出正确判断；
- 多个文件之间没有重复维护同一内容。

## 阶段三：确定性辅助脚本

只有重复操作需要确定性时才添加脚本，例如校验、评分、转换或聚合。

完成证据：

- 脚本具有明确的输入输出契约；
- 代表性的成功和失败案例已在本地运行；
- 不阅读无关实现细节也能理解整个工作流。

## 阶段四：行为评估

建立包含正向、负向和边界情况的小型评估集。

完成证据：

- 成功标准检查实际行为，而不是措辞或标题；
- 已知失败被保存为回归案例；
- 改进后的版本同时通过旧案例和新案例。

## 阶段五：基于证据维护

根据真实失败做窄范围更新，并练习判断新信息应该放入 `SKILL.md`、参考文件、脚本、仓库规则还是任务状态。

完成证据：

- 修改引用了具体观察；
- 只修改最相关的文件；
- 删除过期指令，而不是只追加规则；
- 对剩余限制有明确说明。

## 建议的第一个项目

创建一个小型“题目复盘” Skill，引导学习者复盘一道已经作答的题目，但把个人错误历史保存在 Skill 外部。验证它能够：

- 在展示答案前先要求学习者提交自己的尝试；
- 找出第一处实质错误，而不只关注最终答案；
- 区分单次错误与重复模式；
- 不因无关请求而触发。
