# Skill 更新规则

只有 Skill 的可复用行为被证明确实错误、不完整、不安全或重复低效时，才更新 Skill。

## 可以支持更新的证据

- 同一个流程判断重复失败；
- 某类请求持续错误触发或持续无法触发；
- 缺失必要的授权或安全边界；
- 工具、数据结构或来源假设已经过期；
- 新流程已在多个代表性案例中验证；
- 评估退化可以定位到具体指令或资源。

## 通常不足以支持更新的情况

- 一道特殊题或一个特殊示例；
- 一次随机的不良回答；
- 任务输入缺失；
- 不影响工作流的措辞偏好；
- 某个任务的临时状态；
- 更适合放入参考文件的领域知识；
- 因工具不可用而不是流程错误导致的失败。

## 更新步骤

1. 保存失败案例。
2. 判断主要责任位置：Skill、参考文件、脚本、仓库规则或任务状态。
3. 写明目标行为和最小修改建议。
4. 条件允许时添加行为回归案例。
5. 应用窄范围修改。
6. 重新执行已有正向、负向和边界案例。
7. 记录实际结果和剩余限制。
8. 删除过期指导，不要只持续追加规则。
